# 通用工程规则（generic-engineering）

> 单源：AGENTS.md 重构（2026-11-13，spec 附录 A#7/#12/#18、附录 B 对应 `→2 generic` 条目
> + 收敛对 L868/871·L870/872）。**通用工程判断前读**——这些教训横跨业务域，
> 埋在业务节里改别的域的人看不见，故上浮至此。

## 判据与测试

- **「就绪/可消费」类判据必须与消费方同源**（2026-10-28 实弹：手写 HTTP 探针测库线
  可拉取，绕开 go 自己的代理解析 ⇒ 同时刻本机 200、runner 上判死，整趟车卡 10 分钟）：
  判据若与真实消费路径不同源，结论就可能长期错——**优先用消费方自己的那套机制当判据**
  （`go mod download` 与 `go mod tidy` 同路），探针只配做兜底。
  **同源 ≠ 同参**（2026-10-29 实录）：路径对了、参数错了照样恒假——探针把版本号
  `TrimPrefix("v")` 后 `go mod download @0.20.4` 报 unknown revision ⇒ **任何**版本
  都被判不可消费、列车卡 10 分钟（连发布十几天的也探不到 ⇒ 先排除「同步中」，
  再怀疑探针）。改探针把每个入参都过一遍；**新写的等待/探针逻辑必须先在真实 CI
  runner 上验一遍**（本机 GOPROXY 与 runner 不同 ⇒ 本机复现不了；推一次性探针
  workflow 到真 runner 量同一时刻行为）。
- **负对照是验收底线**（2026-10-26 实录，5 处全绿）：每条新断言都要能把实现改回缺陷态
  并**实跑变红**——「测试绿」只证明「当前实现如此」，不证明「断言钉住了行为」。
  修 bug 先写复现测试；覆盖率按模块只升不降。
- **拆开一个判定 = 逐个重审所有以它为闸的门**（2026-10-24 实录）：`IsExpired()` 拆出
  「次数耗尽」后四个面的漏闸。拆分前「这个门同时挡了什么」是**隐含契约**，
  拆分时要显式继承：`grep` 把判定点全捞出来逐个对照，别凭印象。
  **零测试的面 = 漏闸不会被发现**。
- **守卫的「发现机制」本身也要能被机械验证**（2026-10-25 实录）：守卫若只信作者自标，
  新增条目忘自标 ⇒ 守卫不红（`preview_share` 就这样漏出契约表的）⇒ 补**客观判据**
  与自标**交叉核对**。同理：契约表要登记**运行时实际会变的属性**（如 HTTP 状态码），
  否则「同语义不同状态码」的退化结构上无法被发现。
- **闸门组合不能靠人记 ⇒ 显式契约表 + 机械守卫**（2026-10-24 实录）：各面手搓闸门
  ⇒ 新加面没人要求声明口径 ⇒ **漏闸是默认结果**。落地：真实注册路由与工具注册表
  双向核对的契约表；条目必须声明「交付什么/口径/由哪个测试覆盖」且**测试函数真实存在**
  （源码树检索防空头承诺）；新增面前缀命中自动进核对，忘登记直接变红。
- **公共查面不替调用方做业务判定**（2026-10-24 实录）：共享层把「次数耗尽」吞成
  NotFound ⇒ 调用方独立错误码永远发不出 ⇒ 判定权归**出口面**，共享层只答「查得到没有」。
  **补闸必须配负对照**，否则「全绿」可能只是断言写错了地方。
- **门禁的判定输入不能是「当前状态」，要是「该状态下应该已到位的产物」**
  （2026-10-24，3.3.24 两阶段各假红一次）：产物在终态前必然落后（hub Release 在推 tag
  后 ~40s 才建）⇒ 跨仓产物只在**终态**强校验，其余态降级告警；终态给有界重试，
  耗尽仍不符照常判红（不削弱门禁）。
- **降级路径的断言必须自证「不是恒真」**（审计#9）：`f(sub) != f(sub)` 恒 false
  ⇒ 这条契约从来没被测过（SA4000）⇒ 比较两次调用结果或钉金标准值。
- **MCP jsonschema 描述里不能出现 `word=`**（2026-10-22 实弹）：SDK 解析 struct tag
  报错并 **panic**，而工具是包初始化时注册的 ⇒ 整台服务端起不来（`count=按取件次数`
  这类文案就踩雷，用 `count 按取件次数` 避开 `=`）。改 `mcp/tools.go` 必须跑
  `TestInitialize`；编译期常量无法调函数生成的问题用**机械互锁测试**兜底。
- **包级全局缓存 ⇒ 用例自带隔离缓存**（审计#4）：TTL 按真实时钟走 ⇒ 上条用例的记录
  下条继续命中 ⇒ 断言依赖运行顺序 ⇒ `-count=2` 必红 ⇒ CI 偶发且莫名。
  ⇒ 用例先换专属缓存 + 源码扫描守卫（调该缓存的测试必须调隔离 helper）。

## 幂等与数据

- **可重试的写操作必须有幂等键**（2026-10-24 实录）：chunk/presign `Complete` 不查
  已建分享 ⇒ 二次 Complete 再建一条 ⇒ 两份各有独立取件额度 ⇒ 「最多取 N 次」实际
  可取 2N。⇒ 以业务键（upload_id）回读复用，且回读放在**副作用之前**。
  通用判据：没有幂等键时「重试」=「重复创建」⇒ 配额语义整体失真。
- **同一列两种语义：先归一数据、再删分支；数据迁移必须 Go 侧幂等实现**（2026-10-26 实录）：
  AutoMigrate 只加列不删列不回填 ⇒ 回填必须写成启动期幂等迁移（两条数据库路径都生效）；
  **读路径的兜底分支是数据迁移的执行点**——删兜底前迁移必须先于任何文件读取完成；
  磁盘布局同层冲突用同盘 rename（幂等、冲突跳过）。
  删兼容前**先审计真实数据**（DB 行形态/磁盘布局），静态看代码会误判「legacy 分支」。
- **软删 + 唯一索引 ⇒ 复活行而不是新建行**（2026-10-26 实录）：唯一索引不区分软删行、
  GORM 默认作用域查不到软删行 ⇒「查不到就新建」撞唯一索引且报错点离病病根很远。
  两个 GORM 静默坑：复用同一 tx 做第二条 UPDATE ⇒ WHERE 被累加（每条语句重新起 tx）；
  `Updates(map)` 里 nil 值被跳过 ⇒ 用 `gorm.Expr("NULL")`。排查：开 SQL logger 看
  **实际生成的 SQL**；`assert.Nil` 对 `gorm.DeletedAt` 值类型永远失败，断 `Valid`。
- **同一事实的多处独立推导要收敛到一个入口**（2026-10-26 实录）：「文件名」4 处各有一套
  取值顺序 ⇒ 同一份文件在不同页面显示不同名字。判据：找「同一事实」被几处独立推导，
  逐处对照取值顺序，收敛到一个函数，其余改调它。**接口测试与单测盖不住**（没有断言
  「名字应该是哪个」）⇒ 必须专门加口径断言。

## 删兼容与契约

- **删「旧版本兼容」前先分三类**（2026-10-25，一轮删 45+ 处）：①旧版本兼容⇒删；
  ②协议/规范兼容（多版本握手、N-1 双格式）⇒**不能删**（对外契约）；
  ③平台/浏览器/依赖兼容（execCommand 降级、ASCII 兜底）⇒**不能删**。
  判据只看代码与契约**不看注释**（注释会失真）。**「零引用」要覆盖
  产品仓 + 本仓脚本/冒烟/CLI + 桌面端**——删掉 `data.token` 时没发现冒烟 S4 就是它的
  用户 ⇒ CI 连锁 401。Cookie 与 Bearer 是**两条并行认证通道**，删载体≠删通道。
  **落地纪律**：不需迁移与需迁移分两批；契约层同步退役并重生成三份产物；
  测试 mock 打在归一化点之下时要改成归一化后的值（那是 mock 不忠实，不是代码错）。
  没有单测覆盖的面改完必须人工过一遍。
- **对外响应里的 `url`/`link` 字段必须实测可用**（2026-10-23，收敛为一条）：
  同名字段三种含义——页面链接（hash 形态）/直链（query 形态）/API 路径（相对）。
  **字段名不承载语义，语义靠实测**；判「坏链」要换方法都试过：页面链接不能直接 GET
  （fragment 不发给服务器）、presign `upload_url` 要 PUT + `X-Upload-Token` +
  与申报大小一致的 body。漏改点按**能力**清点（同一能力多个出口），不按已知点位。
- **按码解析只有一处真相源**（2026-10-23，收敛为一条，取六处共用版）：
  解析优先级 ①6 位取件码（真相源 `pickup_code`）②分享码精确 ③大小写折叠，
  分享/预览/匿名/MCP/多文件子项/管理面六处共用。配套两硬规矩：**跨列避让**
  （铸造取件码避开 `code` 列、自定义码避开 `pickup_code`，两侧都做且铸造侧用**折叠**检查）；
  **失败记账用规范分享码**（用原始入参 ⇒ 8 位与 6 位各一把钥匙 ⇒ 爆破预算翻倍）。
  （占位分享判定 `IsNotReady` 见 contributing-rules 对外契约节。）
- **静默失效一律改成响亮失败**（2026-10-22 定的口径）：用户能提交一个「看起来生效、
  实际不生效」的参数 ⇒ 就是缺陷（实录：非法过期样式被静默过滤；`expire_style=count`
  被忽略 ⇒ 用户拿到「30 天+无限次」错配）。**静默降级比报错危险得多**
  （实录：`pb put -p` 吞密码 ⇒ 建出**公开**分享，命令还成功返回——危险的不是命令写错，
  而是安全语义被悄悄放宽）。
- **已知旗标的缺值必须报错**（审计#5）：同上一条的 CLI 面。
- **按固定长度切片外部输入 = 越界 panic 温床**（2026-10-25 实录）：IdP 返回短 sub
  ⇒ `claims.Sub[:8]` panic ⇒ 全部 OIDC 登录 500。外部输入长度不受你控制 ⇒
  sha256 指纹（与长度无关+不碰撞）或显式判长度；取前缀还会撞唯一索引。

## 文档与提交

- **对外文档的示例必须来自真机响应；验证脚本必须真跑过**（2026-10-23 实弹）：
  文档曾成体系教错（死链/成功码错/密码通道废/必填写成有默认值），照抄即坏且
  没有任何测试会发现；e2e 脚本判 `code==200`（实际 0）⇒ 第 1 条断言就红、
  **脚本从来没跑通过，绿灯是假的**。⇒ 示例按真机 ground truth 校准；
  脚本改完当场实跑一遍再入库。
- **`git commit -m` 会被 shell 吞内容**（反引号/`$(...)`/括号）⇒ **一律 `-F 文件`**。
- **shell 变量紧跟全角标点 ⇒ bash 把字节吃进变量名**（2026-10-23 实弹）：写
  `"…（$VAR）"` 时 UTF-8 locale 下全角字节并进变量名 ⇒ `set -u` 当场 `unbound variable`
  ⇒ **变量后紧跟任何非 ASCII 一律 `${VAR}`**；改完用 `scripts/check-shell-var-boundary.sh`
  扫（门禁已在，别消音）。
- **`while` 放进管道 ⇒ 循环变量不外传** ⇒ 标志位恒 0 ⇒ 门禁永远绿 ⇒
  一律重定向喂输入（`done < tmpfile`）。
- **分支保护 API 三个坑**（审计速记）：legacy protection 改动需 admin（本地凭据 404
  ⇒ 走 ruleset）；ruleset payload 不能带 `integration_id: null`（422）；
  `GET /rulesets` 概要**不含 rules 详情**（逐个按 id 取）；gh 的 `--input -` 不生效
  （写文件）；job 显示名含空格中文必须逐行进数组。
- **CI 的 Go 版本钉到 toolchain 地板 + job 级 `GOTOOLCHAIN: auto`**（审计#2）：
  浮动 minor 会拿到低于地板的 patch ⇒ 构建阶段就死、门禁变噪声；setup-go v7 强制
  local。全生态由 `hub/scripts/check-go-version-floor.sh`（带 `--selfcheck` 变异自证）守。
- **发版前必须扫全生态 CI 的 `main` 分支**（审计#1）：不是只看要发的那几个仓——
  core 曾在 main 连红两趟车（依赖地板抬升后上游截断语义变了、断言没跟）。
  ⇒ **依赖升级后必须重跑受影响包的断言**，不能只看 `go build` 过。
- **冒烟若会改目标实例的配置**（审计#7）：必须 trap（EXIT/INT/TERM）+ 还原后**回读比对**，
  且「读原值失败/解析失败/写回失败/回读不一致」四条路径都计入失败——否则绿冒烟把生产
  留在降级态。
- **门禁脚本用 CI 同版本的 linter 验**（审计#8）：本地 brew shellcheck 与 CI apt 版
  告警集不同 ⇒ 本地绿 CI 红。**门禁脚本要自证「我跑过了」**：开头打印扫到几条，
  扫不到直接判红。
- **跨仓不变量要有跨仓对账门禁**（审计#6）：一个仓的门禁扫不到另一个独立仓
  （Helm 键名不匹配/清单已改流水线没改）⇒ 每个涉及的仓都得有自己的断言。
- **先通后优的换源有亚毫秒竞态**（审计#10）：收到换源消息 ≠ 自己的新承载已就位
  ⇒ 双方读写不同流 ⇒ 随机 60s 超时，且 CI 比本地更易复现（负载拉宽窗口）。
  ⇒ 换源必须等新承载就位（有界预算），等不到报明确错误；「本地过了」不等于没竞态。
