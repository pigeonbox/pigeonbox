## 1 背景：为什么必须重构（2026-11-13 源码取证）

| 问题 | 事实 |
|---|---|
| **注入截断** | 895 行 / **207KB**；agent 上下文预算 32KB ⇒ 每次注入被截断到约 1/7，**尾部规则（L600-895）长期读不到** |
| **两大块占 124KB** | `## 版本与代码规则（强制）` L781-895：115 行/**64KB**（事故实录砌成的规则墙）；`## 生态仓库` L5-38：34 行/**60KB**（表内逐仓沿革长文） |
| **无版本控制** | 工作区根不是 git 仓 ⇒ AGENTS.md 无历史、无 diff、无回退；重构=无版本的重写，**备份是唯一后悔药** |
| **机器写入锚点** | `trainctl bump`（bump.go L1028-1066）按 **行首格**（如 `` `PigeonBox/fnos/` ``）匹配表格行、改**末格**版本单元格，15 行键固定（见 §6）；表形态不能破坏 |
| **双份口径** | `CONTRIBUTING.md`「硬性规则（CI 强制）」与 AGENTS.md 重叠（依赖单向/生成物/破坏性/钉版），两处维护必然漂移 |
| **行号引用会漂** | 仓内/文档存在「AGENTS.md L###」式引用（`cigate.go:5` 引 L875 等）——重构后行号全错 |
| **语义重复** | L868↔L871（url/link 字段实测）、L870↔L872（按码解析真相源，872 是更新版）等，措辞不同机械去重抓不到，必须逐段审 |

**消费方盘点**：①agent 注入（32KB 预算，主消费方）；②`trainctl bump` 机器回写版本矩阵；
③仓内注释/脚本的「AGENTS.md L###」与「见 AGENTS.md」引用；④人读（低频）。

## 3 三层架构与分流判据

```
AGENTS.md（层1 · 工作区 · ≤24KB · 每次注入）
 ├─ 永真硬规则精编（违反代价高且每次任务都可能撞的）
 ├─ 生态仓库索引表（⚠️ bump 机器回写锚点：行首格/末格结构冻结，见 §6）
 ├─ 常用命令入口 / 发车必守点压缩版 / worktree 纪律
 └─ 指针索引 → 层2 / 层3（每条一句话「什么时候来读我」）
层2 PigeonBox/docs/rules/*.md（hub 公开仓 · 版本化 · PR + 既有文档门禁）
 ├─ contributing-rules.md   提交约定 / 依赖单向 / 生成物 / 破坏性升版 / 钉版（单源，CONTRIBUTING 指过来）
 ├─ ci-gate-failures.md     门禁失效形态 / 等 CI 假信号 / git 有界取数（脱敏后：只留机制）
 ├─ release-rules.md        发版纪律（发车顺序、库线钉版、守门、切镜像判据）
 ├─ frontend-rules.md       前端细则（折叠屏/列宽/CSS 特异度/路由/表格形态）
 ├─ brand.md                品牌真相源/换色生成器/色板公式（对应现有 docs/brand/）
 └─ generic-engineering.md  幂等键 / 拆判定重审 / 守卫自证 / 静默失效响亮失败 / 负对照底线…
层3 工作区 docs/topics/*.md（按需读 · 不公开 · 含内网细节）
 ├─ incidents/   事故实录压缩档案（教训+证据日期；死条目不建档）
 ├─ deploy.md    部署面/端口/机器/热修史/网络拓扑（敏感，永不入仓）
 ├─ repos.md     逐仓沿革详解（与各仓 Release notes 重复处直接删、指过去）
 └─ workspace.md 工作区环境细节（setup 加固史、探针配方、本机网络坑）
```

**分流判据（一句话）**：公开安全且是「规则」→ 层2；含内网/机器/部署细节或「历史现场」→ 层3；
「每次任务都必须知道」→ 层1。**拿不准进层3**（不公开的代价只是少版本化，泄密不可逆）。

**四条特别处理**（§设计确认过的）：
1. **已有真相源的节**（取件计次 84 行→设计稿、品牌色 54 行→scripts+docs、能力演进 24 行→规划稿、
   changelog 页 31 行→docs-site 机制）→ 层1 各留「核心语义一行 + 指针」，重复原文删除
2. **64KB 规则墙**（L781-895）→ 主战场：逐条按附录 B 拆入三层
3. **通用教训上浮**：取件计次 17 条里的幂等键/拆闸重审/守卫自证等**跨域通用条目**→ 层2，
   取件专属语义→设计稿指针——避免「教训埋在业务节里，改别的域的人看不见」
4. **行号引用**→节名引用（`cigate.go:5` 等随层2 PR 一并修）

## 5 风险与场景抽查

| 风险 | 缓解 |
|---|---|
| 无版本控制改坏不可回退 | Step 0 备份 + sha256；两步走，Step 1 独立可合 |
| 分流丢信息 | 附录 A/B 全覆盖（零漏项）+ 场景抽查反查 |
| **敏感信息进公开仓** | Step 1 脱敏门（内网模式 grep 清零）+ gitleaks + 人工复核；拿不准进层3 |
| bump 锚点被破坏 | 表结构冻结（§6）+ G4 dry-run 断言 + 守卫④ |
| 行号引用漂移 | G5 grep 清零（仓内随 Step 1 PR） |
| 与在途 bump 撞车 | Step 2 前确认 train state=shipped、无在途 bump（bump 写同一张表） |
| 抽查形式化 | **真子代理**：派 explore 子代理（继承新 AGENTS.md 注入）答题 |

**场景抽查（5 题，验收 G6）**：每题派一个只带新 AGENTS.md 注入的子代理提问，答案须**沿新指针链**
找到规则并引用新路径（节名/文件名，而非旧行号）：
① 4.8.3 那次 BEHIND 卡合并，人工兜底怎么做、根因是什么？
② chunk 续传为什么不能重新 init？
③ 同机另一会话在改 core，我动手前的纪律是什么？
④ 发车前库线钉版要人算吗，什么时候必须传 SET=？
⑤ 管理台表格加一列，窄屏裁切怎么验？
通过标准：5 题中 ≥4 题一次答对且引用新结构（第 5 题若指向层2 frontend-rules 即算对）。
