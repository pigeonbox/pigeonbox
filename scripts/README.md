# scripts/

装配仓(hub)级脚本。模块仓各自的工具在自己的仓里（如 `contracts/scripts/` 的 IDL 再生成）。

| 脚本 | 用途 | 说明 |
|---|---|---|
| `setup.sh` | 拉齐/更新十二个模块仓（幂等），`make setup` 的实体 | 默认全拉 contracts/core/server/frontend/fnos/openwrt/p2p/kit + NAS 打包四仓 synology/qnap/ugreen/terramaster；`SETUP_<名>=0` 可分别跳过。**2026-11-02 加固**：① 取数走 `git-fetch-safe.sh`（**超时+重试**；裸 git 在链路瞬断时会挂住 ⇒ 整个 setup 无限等）；② **默认分支解析** `origin/HEAD`（fnos 是 `master` 不是 `main` ⇒ 硬编码会报 "couldn't find remote ref main"）；③ 默认**切到默认分支**再快进（旧列车分支如 `train/4.6.7-fix` 是遗留，留在上面会让本地联编用旧代码；`SETUP_KEEP_BRANCH=1` 可保留当前分支）；④ **脏仓守卫**（有未提交改动 ⇒ 不切分支、不拉取，可能是同机并行会话的工作）；⑤ 取数失败的仓**跳过并记账**、末尾统一报（不给「工作区就绪」假结论），退出码 0=全拉齐 / 1=有仓未拉齐 |
| `smoke-full.sh` | 全能力真机冒烟（44 项断言，含临时 Redis） | 需先 `make build`，对运行中的 server 执行。**2026-11-10 加固（pigeonbox#322/#323）**：① **管理口令来源探测链**——`SMOKE_ADMIN_PASSWORD` → `$PIGEONBOX_DIR/.env`/`./.env`/`/opt/pigeonbox/.env` 的 `PB_ADMIN_PASSWORD` → 回落 `admin123`（回落时**明确提示**用了默认口令）⇒ 改过口令的站不再 16 条连环假红；② **探针自助回收**——每次造探针都登记分享码，收尾经**管理端**回收并终验断言「登记码在管理端查不到」（S31）⇒ 冒烟不再在目标实例留残留（实测：回收后 file_codes / 文件清单 / 物理文件计数都回到运行前）。**2026-11-10 再加固（pigeonbox#333）**：③ **本轮独占 scratch 目录**——fixture 与产物一律写到 `${SMOKE_RUN_DIR}`（`run-<时间戳>-$$`，退出时自清理）⇒ 躲开「别的属主的旧产物」造成的假红/假绿（`curl -o` 覆盖不了属主旧文件 ⇒ rc=23 ⇒ 断言读到上轮产物），并避免每轮堆积 ~300KB；④ **回收口径改精确匹配**——管理端列表项**只回分享码、不回 `pickup_code`**，而匿名生成/访客投递/presign 只回 6 位取件码 ⇒ 改走 `GET /admin/files/:id` 用 `share.code`/`share.pickup_code` **精确相等**确认（**不用**「keyword 命中数==1」，那是五列 LIKE，会误删他人分享），并**硬删 `/admin/files/purge`**（软删行仍占 `COUNT(*)` ⇒ 对账照样红）；⑤ **S31 三态**（已回收/残留/**未核实**）——「没核实成」不算绿灯；⑥ **S32 判据方向纠偏**——旧判据「存活总数 ≥ 基线」**永远绿**，改为**净增 0 才绿**，净增时用 `created_after` 圈出新增行逐条归因（探针残留 vs 他人新建，两种成因分开报）；⚠️ `created_after` 必须 `--data-urlencode`（query 里的 `+` 会变空格 ⇒ 服务端静默丢条件）**且**偏移要用 `+08:00`（Go 的 RFC3339 不接受 `+0800`），服务端「解析失败即静默丢条件」本身是独立缺陷 ⇒ core#102 |
| `e2e-api-key-smoke.sh` | API Key 全链路 e2e（创建/认证/限流/撤销） | 对运行中的 server 执行 |
| `e2e-chunk-upload.py` | 大文件分片上传 e2e（init/分片/complete/秒传） | Python3 标准库实现 |
| `e2e-s3-minio.sh` | MinIO S3 存储后端 e2e | 本地起 MinIO 容器后跑通 S3 读写与分享 |
| `export_config_from_db.{go,py}` | 从旧版 SQLite `key_values` 表导出配置为 YAML | **遗留迁移工具**：`key_values` 表已废弃（现行为 `system_configs` 单行 JSON，由 core 自动读写），仅用于迁移更早期部署的数据。Go 版需独立构建：`cd scripts && GOWORK=off go run export_config_from_db.go -db data/fileCodeBox.db` |
| `generate_favicon.sh` | 品牌图标生成入口（薄封装，转调 `gen-brand-icons.py`） | 前端/静态资源维护用 |
| `gen-brand-icons.py` | 品牌图标**换底色 + 全套派生资产**重出 | 真相源 `frontend-core/public/favicon.svg`（内嵌 512px PNG）+ 白鸽贴片 `pigeon-glyph.png`；底色公式与站内 logo 底座一致。`--accent 1677ff` 换色并重出（frontend-core/fnos/desktop/synology/qnap 全套），不带参数只重出派生件 |
| `test_nfs_storage.sh` | NFS 存储后端连通性与读写测试 | 存储运维用 |
| `wait-pr-checks.sh` | 等一个 PR 的 checks 到达**终态**并给三态结论（等 CI 用） | 退出码自有语义：**0=全绿 / 1=有失败 / 2=超时（不是失败）/ 3=用法错误**。判定按「检查名取**最新一次** attempt」（与 `release/trainctl/advance.go` 的 `checksAllGreenLatest` 同口径），**不用** `gh pr checks`（它按所有 attempt 判定 ⇒ 重跑前的失败会污染判绿）。别再写 `sleep N; gh pr checks`：`gh` 的退出码 **8=还在跑**（不是失败），`2>&1` 只并流不并码 ⇒ CI 绿着会被报成失败。`--selfcheck` 用合成数据自证（不依赖网络） |
| `git-fetch-safe.sh` | **有界**的 git 取数（fetch/pull/clone）+ 正确比对本地与远端 | 每次 git 操作有**超时上限** + 有限重试 + 退避；退出码三态分离：**0=成功/同点、1=失败/有差异、2=超时（不是失败）、3=用法错误**。`compare` 比**同一 ref 的两端**（`<ref>...origin/<ref>`）并打印两端 SHA 与「本地独有/远端独有」计数——**别拿 HEAD 去比 origin/main**（在 feature 分支上是假分叉）。为什么必须有：git 的网络操作在链路瞬断时**会挂住**（ssh 层无进展 ⇒ git 不自行放弃）⇒ 无界的调用方被拖死（agent 后台任务 60s 被杀只剩半截输出、`make setup` 无限等、trainctl 的 fetch 拖满 6 小时 CI job）。`--selfcheck` 用**假 git**（PATH 注入）自证，不依赖网络 |
| `git-push-via-api.sh` | **github.com:443 不可达时的推送兜底**（Git Data API：blob→tree→commit→ref） | 实录（2026-11-04）：本机到 github.com 会**彻底不通**（connect timeout，curl 直连返回 000），而 **api.github.com 仍可达** ⇒ git 协议推分支全废、REST API 照常 ⇒ 本脚本走 API 把分支推上去。与 `git-fetch-safe.sh` **互补**：那个管「**慢/抖**」（超时+重试），这个管「**彻底不通**」。**安全设计**：① **内容完整性闸门**——远端返回的 blob sha 必须与本地 `git hash-object` **逐字相同**，否则立即中止且**不建 commit/ref**（杜绝「传输坏了却看起来推成功了」）；② **不静默改写历史**——目标分支已存在且不等于基线时默认拒绝（要 `--force`）；③ 基线相同时走快进更新；④ 作者/提交者不写死，交给 GitHub 按 token 身份填。`--selfcheck` 用**假 gh**（`PB_GH_BIN` 注入）离线自证 4 组用例（正常⇒绿 / 内容损坏⇒红且不建 ref / 改写历史⇒红 / 快进⇒绿），已接进 CI |

> 来源说明：`export_config_from_db.*`、`generate_favicon.sh`、`test_nfs_storage.sh` 收编自旧单体仓库（legacy/PigeonBox），2026-10 迁入；`e2e-*` 与 `smoke-full.sh` 为本项目 2026-10-03 新写；`gen-brand-icons.py` 为 2026-10-26 品牌换色时新增（`generate_favicon.sh` 的实体）。
